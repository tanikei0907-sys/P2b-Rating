# P4：走破タイム差を用いたオンライン更新重みの検証報告

**結論：P4を新採用候補として確定します。検証Fの標準PL-NLL差は-0.010217695、95%CI上限は-0.008220374で、有意な改善を確認しました。**

## 1. 資産保護とモデル設計

- P2b config SHA-256：`3577cbc7a6a2c3e58bfdeda6666b9aa9d7369866f4c6fa49902dac6b8779dbe9`
- P4選択config SHA-256：`436f08ffb840a60ef33354fc28fa9434d0193a0460c73ba8c8f29d8038a26ba1`
- P0・P2b・P2b継続更新出力と凍結configは変更していません。DBは一時コピー経由の読み取り専用接続です。
- 探索は2012～2020年、検証は2021～2024年です。探索時には検証期間のレースを入力へ含めていません。
- P1デビュー形態、P2b血統係数・κ=20・標準化定数、P0のκ・q=0.01・分散、W_shareを維持しています。
- 初期3走残差はP4の発走前スコアから計算し、開催日終了後に血統集計へ反映しています。
- **評価NLLは常に標準W_share PL-NLLです。マージン倍率は勾配・対角情報量の更新だけに使用しています。**

方式Aは段階kの`W_share[k]`へ`min(m_max, 1+γf(Δt_k))`を乗じます。方式Bは`g=0.75f(Δt_1)+0.25f(Δt_2)`（Δt_2がない場合はf(Δt_1)）を用い、レース倍率を`clip(1+γg,m_min,m_max)`とします。距離正規化時は`f(Δt)=Δt/(距離/1000)`、それ以外は秒です。

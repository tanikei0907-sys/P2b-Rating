# 依頼：中央競馬（平地）レーティング算出
## 賞金配分重み付きPlackett–Luce＋時系列オンライン更新（特徴量候補用）

## 0．目的・用途・厳守事項

### 0.1 目的

中央競馬（JRA）の平地レースについて、着順・斤量と前日までの状態だけを使い、JRA所属馬の基礎的な強さ指標を時系列で推定する。

各レースについて、**発走前のスナップショット**を保存し、後続の予想モデルで追加特徴量候補として検証できる形にする。

本依頼は、レーティング単独の予想器や馬券戦略を作るものではない。したがって、次は本依頼の範囲外とする。

- レーティング単独での馬券購入条件の作成
- オッズ・人気・支持率・払戻・予想タイム指数の使用
- 馬券収支や市場優位の評価
- 後続のLightGBM等への実装、特徴量の採否、後続モデルの性能評価

レーティングの勝率出力は、あくまで較正・健全性の診断に使う。実際に後続モデルへ渡す候補は、原則として `mu_pre`、`var_pre_persistent`、`var_pre_eff`、`m_pre`、経験数、不確実性、補助状態であり、単独予想の最適化そのものを目的にしない。

### 0.2 対象範囲

対象は、**JRA主催の平地競走（JRA主催の交流競走を含む）**とする。

次のデータは、レーティング算出、グラフ内出走数の判定、血統集計、評価のいずれにも使用しない。

- 障害競走
- 地方競馬主催レース
- ばんえい競馬
- 海外開催レース
- JRA主催レースに出走した、当該レース時点でJRA所属でない馬の出走記録

非JRA所属馬の扱いは、第2.6項に一本化する。データベースに不要データが含まれる場合は、可能な限り抽出時に除外し、読み込み直後にも再検査する。

### 0.3 期間とロック

期間は次のとおりとする。

| 区分 | 期間 | 使用目的 |
| --- | --- | --- |
| ウォームアップ | 2012-01-01～2016-12-31 | 状態更新のみ。評価しない |
| 調整期間 | 2017-01-01～2020-12-31 | ハイパーパラメータ・事前分布・診断用温度の決定 |
| 検証期間 | 2021-01-01～2024-12-31 | 凍結した設定の検証・比較・報告 |
| ロックデータ | 2025-01-01以降 | 本依頼では入力・学習・評価に使用しない |

**後続の予想モデルの最終ホールドアウトは2025年以降とする。** 2021～2024年は、このレーティング候補の検証・比較には使用してよいが、その結果を見て、ハイパーパラメータ、重み、縮約、事前分布、判定基準を変更してはいけない。

2025年以降のデータは、抽出時に含めない。読み込み後に2025年以降の行が見つかった場合は、件数を記録して作業を止め、データ抽出条件を確認する。除外してそのまま継続してはいけない。

### 0.4 段階停止

作業は次の3段階とし、各段階の終了時に必ず停止して確認を求める。

1. 段階1：データ確認
2. 段階2：P0（全馬共通の事前分布）の実装・調整・検証
3. 段階3：血統事前分布（P1・P2）

承認なしに次段階へ進まない。段階2・3の検証結果を見て、設定を変更する場合は、承認済みの独立した新しい開発系列として扱い、同じ検証期間を未使用テストとはみなさない。

## 1．データ

### 1.1 入力

```text
入力：【ファイルパス、またはDB接続方法】
抽出元：馬王Z
対象期間：2012-01-01～2024-12-31
対象競走：JRA主催の平地競走（交流競走を含む）
```

想定列は次のとおり。実際の列名・意味・型は、段階1で確認して報告する。

- レース識別子
- レースの開催側体系（JRA／地方など）
- 開催日
- 競馬場
- 芝・ダート・障害の区別
- 距離
- クラス・競走条件（新馬戦・未勝利戦などを含む）
- 元の頭数
- 馬ID
- 馬番
- 確定着順
- 同着・降着・失格・競走中止・取消・除外の区別
- 斤量
- 父の馬ID
- 母父の馬ID
- 各出走馬の、当該レース時点の所属体系 `horse_affiliation_circuit`（JRA／地方／海外など）

データベースの制限として、次を明記する。

- 明示的な結果利用可能時刻 `result_available_at` は存在しない。データの作成年月日を、結果利用可能時刻の代替として使用しない。
- 交流競走フラグは存在しない。交流競走の件数・層別比較・フラグによる診断は行わない。JRA主催の平地競走に含まれる交流競走は、フラグではなく開催側体系で対象へ含める。

### 1.2 対象レースと評価集合

対象レースは、JRA主催の平地競走とする。交流競走も含めるが、交流競走フラグはデータベースに存在しないため、交流競走の識別・集計には使用しない。第2.6項に従い、各レース時点の非JRA所属馬を除く。

評価集合は次で定義する。

- **E**：新馬戦・未出走戦を除外し、非JRA所属馬の除外後に `n_graph_starts = 0` の馬が4頭以上いるレースを除外し、残った馬が2頭未満のレースも除外した集合
- **E_clean**：Eのうち、非JRA所属馬の除外が一度も発生していないレース集合
- **F**：新馬戦・未出走戦や初出走馬数による除外を行わない参考集合。ただし、残った馬が2頭未満のレースは除外する

EとE_cleanは、除外処理による推定対象の違いを確認するため、必ず並列して報告する。結果を見て、どちらか一方だけを都合よく採用しない。

評価は2017-01-01以降のレースについて行う。それ以前はウォームアップとして状態更新だけを行う。

### 1.3 段階1の報告

段階1では次を報告し、ここで作業を止める。

- 列一覧、型、欠損率、行数、レース数、年別件数
- 除外した行・レースの件数（障害、地方主催、ばんえい、海外開催、2025年以降。理由別・年別）
- 対象レースで除外した非JRA所属馬の出走数・馬数（所属体系別・年別。交流競走の識別は行わない）
- 除外後に残った馬が2頭未満になったレース数
- 馬ID数、父・母父ID欠損率、斤量欠損率、`horse_affiliation_circuit` 欠損率
- 同着・競走中止・降着・失格・取消・除外の件数
- 同じ馬が同日に複数レースへ出走している件数
- 新馬戦について、発走前に `n_graph_starts > 0` の過去グラフ内出走記録がある馬がいないかの確認（該当出走数・馬数・レース数・年別）
- 他経路馬の疑いの診断：データ開始から1年経過後に、新馬戦以外でグラフ内初登場となった馬の数（年別）

明示的な `result_available_at` はデータベースに存在しないため、有無・欠損率の報告は行わない。データの作成年月日を結果利用可能時刻の代替にしない。開催日順の処理は第3.1項に従う。

最後の診断のためだけに、除外した地方・障害・海外の結果を参照してはいけない。

## 2．モデル定義

### 2.1 永続状態

各JRA所属馬は、次の永続状態を持つ。

```text
mu              : 強さの平均。大きいほど強い
var             : 強さの不確実性（分散）
last_start_date : グラフ内での最後のJRA所属出走日
n_graph_starts  : グラフ内での出走数
var_cap         : 休養による分散増加の上限
prior_type      : P0 / P1 / P2a / P2b
```

`n_graph_starts` は、JRA所属としてJRA主催の平地競走に出走した回数とする。交流競走へのJRA所属としての出走を含む。障害・地方・海外、および非JRA所属時の出走は数えない。

### 2.2 発走前スナップショット

レース開催日をDとする。第2.6項の除外後の各馬について、**永続状態を変更せず**、次の一時的なレース用状態を計算する。

#### 休養による不確実性の増加

```text
days_since_start =
    max(0, D - last_start_dateの日数)

var_pre_eff =
    min(var + q × days_since_start / 30, var_cap)
```

- 初登場で `last_start_date` が未設定の馬は、休養日数を0とし、休養補正を行わない。
- `var_cap` は、P0なら `var0`、P1・P2なら該当するデビュー形態の `var0_d` とする。
- `var_pre_eff` は今回の更新に使う一時値であり、永続状態の `var` をこの時点で上書きしない。

#### 斤量補正後スコア

```text
mean_weight = 残った馬の斤量の平均

m_i = mu_i - beta_kg × (weight_i - mean_weight)
```

斤量が欠損の馬は、残った馬の平均斤量を代入して補正なしとする。欠損件数とレース数を報告する。平均斤量には、取消・除外・非JRA所属馬を含めない。

スナップショットには、少なくとも `mu_pre`、`var_pre_persistent`、`var_pre_eff`、`m_pre`、`days_since_start`、`n_graph_starts` を保存する。

### 2.3 賞金配分の重み付きPlackett–Luce尤度

配点 `(100, 40, 25, 15, 10, 0)` に基づく重みを使う。`W_share`・`W_pts` の小数を手入力せず、配点配列からコード内で計算する。

```python
import numpy as np

PRIZE_POINTS = np.array([100, 40, 25, 15, 10, 0], dtype=float)

W_share = PRIZE_POINTS[:5] / PRIZE_POINTS.sum()

PRIZE_GAPS = -np.diff(PRIZE_POINTS)
W_pts = PRIZE_GAPS / PRIZE_GAPS.sum()

W_win = np.eye(5, dtype=float)[0]

# 既存の比較用スキーム。賞金配点から導出するものではない
W_win_heavy = np.array([80, 10, 5, 3, 2], dtype=float)
W_win_heavy = W_win_heavy / W_win_heavy.sum()
```

実装では、配列同士の演算を配列ライブラリのベクトル演算で行う。生成後の各重みについて、長さ5・非負・合計1を検査する。`W_win_heavy` は賞金配分から導出するスキームではなく、既存の比較条件を整数比率で保持するものであり、新たな小数設定を追加しない。

第2.6項の除外後の出走馬について、確定着順のある馬数を `r`、出走馬数を `n` とする。取消・除外馬は、最初から含めない。

確定着順（除外後の相対順位）を `π_1, …, π_r` とし、段階kの候補集合を次で定義する。

```text
R_k = {π_k, …, π_r} ∪ {順位のない馬}
```

順位のない馬は、最下位グループとして各候補集合に残すが、その馬が選ばれる段階はない。

```text
p_ik = exp(m_i) / Σ_j∈R_k exp(m_j)

L = Σ_k=1～K w_k × log p_(π_k,k)

K = min(5, r, n - 1)
```

数値計算では、各候補集合で `max(m)` を引いてからexpを計算する。

- 6着以下の馬どうしの順序は使わない。
- `n < 2` または `K = 0` のレースは尤度なしとし、更新・評価を行わない。
- 重みは **Kに応じて再正規化しない**。

`K < 5` の場合、使用する重みの合計は1未満となる。例えば2頭立てでは `K = 1` なので、W_shareなら重み合計は約0.5263となる。すなわち、少頭数レースや確定着順が少ないレースでは、1レース当たりの有効な証拠量が小さくなる。**これは、観測された着順段階が少ないことを証拠量に反映させるための明示的な設計であり、バグではない。** この仕様を後から結果を見て再正規化へ変更しない。再正規化方式を検討する場合は、独立した別の開発系列とする。

### 2.4 対角近似によるオンライン更新

重み付きPL対数尤度の、各馬の平均強さ `mu_i` に対する勾配と対角情報量を使う。

```text
g_i = Σ_k w_k [ 1(i = π_k) - 1(i ∈ R_k) × p_ik ]

h_i = Σ_k w_k × 1(i ∈ R_k) × p_ik × (1 - p_ik)
```

`h_i` は、PLの情報行列の対角成分である。候補馬i・j間には、非対角項 `−p_i p_j` も存在する。本実装は、計算量を抑えるための**対角近似オンライン更新**であり、厳密な多変量Newton更新ではないことを明記する。

レース前の一時分散 `var_pre_eff_i` を使い、次で更新する。

```text
prec_i = 1 / var_pre_eff_i + κ × h_i

mu_new_i = mu_i + κ × g_i / prec_i

var_new_i = 1 / prec_i
```

`κ` は1レースの証拠の強さとする。

更新後、`mu_new_i`、`var_new_i` を永続状態として保存する。状態更新時に `mu` の値を変更しない馬についても、後述の出走数・最終出走日の扱いを適用する。

#### 確定着順がある馬

```text
n_graph_starts += 1
last_start_date = D
```

#### 競走中止・失格など、公式に順位がない馬

- 候補集合には残し、他馬の尤度には影響させる。
- その馬自身の `mu`・`var` は更新しない。
- 実際に出走しているため、`n_graph_starts` と `last_start_date` は更新する。
- 更新を飛ばした件数を報告する。

#### 取消・競走除外

- レースの出走馬集合から除外する。
- `n_graph_starts`、`last_start_date`、状態を更新しない。

公式記録でも理由が不明な順位欠損は、中止・失格と推測して補完せず、作業を止めて確認する。

### 2.5 同着の処理

同着を馬番順で処理してはいけない。馬番・馬IDは順序の決定に使用しない。

同着グループについて、可能な順列を列挙し、各順列について勾配・対角情報量を計算して平均する。**平均した更新量を使って、各馬を1回だけ更新する。**

```text
g_i_tied = mean_over_permutations(g_i_permutation)
h_i_tied = mean_over_permutations(h_i_permutation)
```

- 2頭同着は両順序を同じ重みで扱う。
- 3頭以上の同着も同様に全順列を扱う。
- 複数の同着グループがある場合は、順列の組合せを用いる。
- 順列の組合せ数が120を超える場合は、馬番順等で近似せず、作業を止めて確認する。
- 評価用の対数尤度も、同じ順列平均規則で計算する。

### 2.6 非JRA所属馬の除外と推定対象

JRA主催の平地競走に出走した馬のうち、`horse_affiliation_circuit` がJRAでない馬は、そのレースの出走馬から除外する。所属判定は、当該レース時点のこの列だけで行う。

除外した馬については、次を行わない。

- 状態の作成・更新
- スコア・尤度・評価の計算
- グラフ内出走数の加算
- 斤量平均・頭数・血統集計への使用

残ったJRA所属馬の着順は、残った馬の中での相対順位に付け替える。同着は同着のまま、順位なしは順位なしのままとする。

PLの部分集合に関する性質は、この**条件付き相対順位**には整合する。しかし、これは実際のレース全体の着順モデルではなく、**JRA所属馬の中での相対的な強さを推定するモデル**である。

評価で使う「勝ち馬」も、残ったJRA所属馬の最先着馬とする。実際の勝ち馬が非JRA所属馬だった場合は、実際の勝ち馬とは異なる。相対順位に適用する賞金配点も、実際のJRA賞金ではなく、JRA所属馬に限定した独自の条件付きスコアである。

この影響を、EとE_cleanの並列比較で必ず報告する。E_cleanは単なる補足ではなく、除外による推定対象の変化を確認するための必須の比較集合とする。

#### 所属変更

- 地方・海外等からJRA所属へ転入した馬は、転入後の出走をJRA所属馬として扱う。転入前の結果は使わず、`n_graph_starts = 0` の初出走馬として扱う。
- JRA所属から他体系へ移った馬の、他体系所属時の出走は除外し、状態を更新しない。
- 後にJRA所属へ戻った馬は、残されたJRA時代の状態を使い、休養による分散増加を適用する。
- 他体系所属の期間も、最終出走日からの経過日数には含める。

交流競走はJRA主催の平地競走に含める。データベースに交流競走フラグは存在しないため、交流競走判定・交流別集計・フラグによる診断は行わない。非JRA所属馬の除外は、すべてのJRA主催平地レースに同じ規則を適用する。

頭数・S0の1/頭数は、除外後の頭数を使う。元の頭数もスナップショットに保存する。

## 3．実装規則

### 3.1 日付・同日処理・結果版管理

開催日ごとに処理する。

1. その日の全レースについて、発走前スナップショットをすべて生成・保存する。
2. その後、抽出時点の確定結果を使って更新する。

同日の他レース結果が、同日のスナップショットへ影響してはいけない。これは厳密な発走時刻ではなく、**当日全レースの前（前日終了時点に相当）**を保守的に再現する処理である。

明示的な `result_available_at` はデータベースに存在しない。データの作成年月日を、結果利用可能時刻や更新順序の代替として使用しない。したがって、本依頼では抽出時点の確定着順を、開催日順に1回だけ処理する。これはデータベースの制限事項として報告するが、作業を止める条件とはしない。

降着・結果修正・データの再抽出については、過去のスナップショットを無断で書き換えず、結果版と更新イベントを記録する。研究用の全期間再構築は別途の作業とし、本依頼の標準処理では開催日順の単一方向更新を維持する。

同じ馬が同日に複数レースへ出走している場合は、件数を報告し、作業を止めて確認する。

### 3.2 ドリフト補正の基準値

新しく現れる馬の初期 `mu` の基準は、as-of日Dの前日時点で、直前365日間に出走した馬の最新 `mu` の平均 `mu_bar_D` とする。

- 各馬の最新値は、Dより前の更新済み状態だけを使う。
- 同日の結果は使わない。
- 直前365日の出走馬がいない場合は、それ以前の直近の利用可能な母集団を使う。
- 利用可能な母集団が全くない初期時点は `mu_bar_D = 0` とし、件数を記録する。平均を無理に補完しない。

### 3.3 グラフ内出走数と初登場馬

`n_graph_starts` は、JRA所属馬として出走したJRA主催の平地競走数とする。

- 交流競走にJRA所属として出走した場合は数える。
- 障害・地方・海外・非JRA所属時の出走は数えない。
- 取消・競走除外は数えない。
- 競走中止・失格は出走として数えるが、`mu`・`var` は更新しない。

初登場馬は、次で区別する。

- データ開始から1年以内に初めて現れた馬：原則として「既存馬（デビュー時点不明）」とし、P0で初期化する。血統・デビュー形態の集計対象には含めない。
- ただし、データ開始から1年以内でも、新馬戦に出走した馬は本当のデビュー馬として扱う。
- データ開始から1年経過後に初めて現れた馬：`n_graph_starts = 0` の初出走馬として扱う。

新馬戦以外での初登場には、地方・障害・海外からの移籍馬が含まれ得ることを、必ず報告書に明記する。

### 3.4 単方向更新と再現性

状態は更新イベントの時系列で、単一方向にのみ更新する。過去のスナップショットは不変とする。

各レースの結果は、原則として1回だけ更新に使う。データの再抽出、後日修正、結果版の重複については、同じレースを複数回更新しないよう、更新イベントIDと結果版を記録する。

## 5．P0のハイパーパラメータ決定（段階2）

### 5.1 P0の初期化

P0では、初登場馬を次で初期化する。

```text
mu0 = mu_bar_D
var0 = 設定値
var_cap = var0
```

### 5.2 探索候補

次の全組み合わせを実行する。

```text
var0       : 0.5, 1.0, 2.0
q          : 0.001, 0.004, 0.01
kappa      : 0.5, 0.7, 1.0
beta_kg    : 0, 0.03
weight     : W_share, W_pts, W_win, W_win_heavy
```

各組み合わせについて、全期間のオンライン更新を行う。

### 5.3 共通の主評価指標：評価用PL-NLL

単独の勝ち馬予想だけを最適化しないよう、主指標は、**固定した評価用重みによる着順全体の負の対数尤度**とする。

評価用重みは、全候補で `W_eval = W_share` に固定する。学習時の重みスキームが異なっていても、評価はこの共通尺度で行う。

```text
EvalPLNLL =
    - mean_over_races(
        Σ_k=1～K W_eval_k × log p_(π_k,k)
    )
```

- 小さいほど良い。
- 発走前スナップショットの `m` を使う。
- K、候補集合、順列平均、非JRA所属馬の除外は第2項と同じとする。
- 評価用PL-NLLにはsoftmax温度を使わない。
- 勝ち馬CEは後述の副次診断とし、これだけで候補を選ばない。

### 5.4 選択

調整期間のEについて、EvalPLNLLが最小の組み合わせを採用する。

- 上位5組を報告する。
- 各ハイパーパラメータについて、他を固定して動かした場合の変化を報告する。
- 最小値の差が小さい場合も、結果を見て新たな候補を追加しない。
- 計算が重い場合は、座標ごとの探索へ切り替えてよいが、理由と探索順を記録する。

選択後、設定をYAMLのconfigとハッシュに保存する。以後の変更は禁止する。

### 5.5 診断用softmax温度

勝ち馬CE等の副次診断に使う温度 `tau > 0` は、選択後のP0について、調整期間の時系列外スナップショットだけで最尤推定する。

```text
p_win_i = exp(tau × m_i) / Σ_j exp(tau × m_j)
```

`tau` は `log(tau)` を使って正の範囲で最適化し、設定値をconfigに保存する。検証期間で再推定しない。

この勝率は診断用であり、後続モデルへ渡す必須特徴量ではない。

## 7．血統事前分布（段階3・承認後に実施）

### 7.1 P1：デビュー形態

第3.3項の初出走馬を、初出走時のレースクラスで分類する。

```text
debut_type = 新馬戦 / 未勝利戦 / その他のクラス
```

各形態dについて、次を設定する。

```text
mu0 = mu_bar_D + b_d
var0_d = 設定値
var_cap = var0_d
```

`b_d`・`var0_d` は、調整期間のEのうち `n_graph_starts <= 3` のレースについて、EvalPLNLLを最小化するように決める。

- 分散は `log(var0_d)` で最適化し、常に正とする。
- `b_d` には小さなL2ペナルティを使い、係数をconfigに事前固定する。
- その他のハイパーパラメータは段階2の値で凍結する。
- 既存馬（デビュー時点不明）はP0と同じ初期化とする。
- 新馬戦以外で初登場した馬には、地方・障害・海外からの移籍馬が含まれ得ることを明記する。

### 7.2 P2：父・母父の産駒成績を初期値の事前情報にする

#### 集計対象

各as-of日Dについて、Dより前に行われた、産駒の「最初の3走」だけを集計する。D当日・同日のレースは含めない。

集計対象は、Eに限らず、対象レース全体（新馬戦・未出走戦を含む、非JRA所属馬除外後）とする。ただし、集計の対象馬は、**新馬戦でデビューした馬に限る**。これにより、移籍馬の成績を血統情報に混ぜない。

#### 残差

各走について、次を計算する。

```text
r_win  = 1（相対順位1着） - e_win
r_top3 = 1（相対順位3着以内） - e_top3
```

`e_win`・`e_top3` は、**P0の発走前スナップショット**からHarville形式で計算する。P1・P2の出力を使わず、P0に固定して循環を避ける。

#### 縮小推定

種牡馬s、母父についても同様に、次を計算する。

```text
X_s = Σ r / (N_s + κ_s)
```

- `N_s`：集計した走の数
- `κ_s`：候補 `{20, 50, 100, 200}` から調整期間で選択
- 産駒が少ない場合は0へ縮約する
- `N_s` と履歴状態を保存する

`N_s = 0` と `X_s = 0` は、平均的な成績ではなく「情報なし」として区別する。

#### 標準化と初期値への変換

`X_sire,win`、`X_sire,top3`、`X_bms,win`、`X_bms,top3` は、調整期間の新馬戦デビュー馬の値で標準化する。

- 平均・標準偏差は調整期間だけで計算して凍結する。
- 標準偏差が `1e-8` 未満なら、分散による割り算を避けてscaleを1とし、中心は調整期間の平均で調整する。異常な拡大をしない。
- 父・母父IDが欠損なら、対応する項を0とし、`ID_MISSING` を記録する。無履歴・ID欠損・通常の0を区別する。
- `κ_s` 候補ごとに、Xと標準化定数を一貫して再計算する。

```text
mu0 = mu_bar_D + b_d
      + beta_sw × X_sire,win
      + beta_st × X_sire,top3
      + beta_bw × X_bms,win
      + beta_bt × X_bms,top3
```

初期分散は `var0_d` とする。

#### β・κの決定

調整期間のEのうち `n_graph_starts <= 3` のレースについて、EvalPLNLLを最小化するように決める。

- βにはL2ペナルティを使い、係数をconfigに固定する。
- 最適化が不安定な場合は、父・母父の2係数への集約を許可する。集約の有無と理由を記録する。
- 検証期間で再最適化しない。

#### 補助集計

父・母父別の、新馬戦勝率、3着内率、初出走から3走以内の勝ち上がり率、産駒数の分布を報告する。補助集計の有利な結果だけを選んで事前分布を変更しない。

- P2b：P1＋父＋母父

### 7.4 段階3の評価・判定

第6項と同じ形式で、検証期間のプール・年別、E・E_clean・Fについて報告する。比較は各モデルと1つ前のモデルとする。

## 8．単体テスト

段階2の最初に実装し、全て合格してから学習・評価結果を使用する。

1. **勾配・情報行列のテスト**
   - 重み付きPLの解析勾配を数値微分と比較する。
   - 対角成分・非対角成分を含む情報行列を数値微分と比較する。
   - 対角近似更新と全行列更新の差を小さな例で報告する。
   - 各重みスキームの合計が1であることを確認する。

2. **合成データでの回復テスト**
   - 既知の強さを持つ仮想馬・仮想レースを生成し、推定 `mu` と真値の相関が収束することを確認する。
   - 対角近似による分散の過小・過大を確認する。
   - 休養・少頭数・同着を含めて確認する。

3. **切り詰め不変性**
   - 日付D以降のデータを除いて再計算し、Dより前のスナップショットが完全一致することを確認する。

4. **将来結果の改変テスト**
   - レースRの着順を入れ替えても、R以前（同日を含む）のスナップショットが変化しないことを確認する。

5. **同日順序不変テスト**
   - 同日レースの処理順を入れ替えても、スナップショットが同一であることを確認する。

6. **シフト不変テスト**
   - 全馬の `mu` に同じ定数を足しても、更新後の馬間差が変わらないことを確認する。

7. **同着・競走中止テスト**
   - 小さな例で手計算と一致することを確認する。
   - 馬番・馬IDを入れ替えても、同着の推定結果が変わらないことを確認する。
   - 順位のない馬が候補集合に残り、自身の `mu`・`var` が更新されず、出走数・最終出走日が所定どおり更新されることを確認する。

8. **非JRA所属馬の除外テスト**
   - 入力から非JRA所属馬を削除しても、全スナップショットと状態が一致すること。
   - 非JRA所属馬の着順を、JRA所属馬の相対順位が変わらない範囲で改変しても、全結果が不変であること。
   - 除外後の相対順位・頭数・斤量平均が手計算と一致すること。

9. **除外データの不使用テスト**
   - 障害・地方主催・ばんえい・海外開催の結果を改変しても、全スナップショットと状態が不変であること。
   - それらの出走がグラフ内出走数に含まれないこと。

10. **分散・初期化テスト**
    - `var_pre_eff` が永続状態を変更せず、更新に使用されること。
    - `var_cap` がP0では `var0`、P1・P2では `var0_d` となること。
    - 初登場馬の休養補正が0であること。

11. **ロックテスト**
    - 2025年以降のデータが入力されていないことをassertで確認する。

12. **結果版・開催日順序テスト**
    - 同じレースを複数回更新しないこと。
    - データの作成年月日を結果利用可能時刻の代替にせず、開催日順で処理すること。
    - 後日の結果修正・再抽出で、過去のスナップショットが無断で変更されないこと。

## 10．停止して確認する条件

次の場合は、推測で補完せず作業を止めて確認する。

- 必要な列がない、または意味が不明
- JRA主催・平地を列から判定できない
- `horse_affiliation_circuit` の欠損が多い、またはJRA所属を判定できない馬がいる
- 同じ馬が同日に複数レースへ出走している
- 新馬戦に、発走前の `n_graph_starts > 0` の馬が1件でも含まれている（新馬戦は未出走馬向けなので、多数かどうかにかかわらず確認する）
- 2025年以降のデータが混入している疑い
- 単体テストが合格しない
- 段階2の判定基準を満たさない
- `mu_bar_D` の日別診断表を出力できない、または `N_min = 100` の前後に基準値・初期値の急変があり、データ・実装の原因を確認できていない
- 同着順列の組合せが120を超える
- 父・母父IDの欠損が多い（例：全体の10％以上）
- 上記の手順を実施できない、または変更した方がよいと判断した場合

各ステップの完了時には、1～2行で経過を報告する。段階1と段階2の終わりでは、必ず作業を止めて確認を求めること。
